# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The diff's changed files and hunks, read against the plan's scope (In and Out) and its Deviations section | Every change in the diff is named in the plan, its Deviations, or the PR description's notes, and every change the plan commits to is in the diff or its absence is disclosed in Deviations or the description. Fails when the diff does more or less than the plan and nothing discloses it. A disclosed shortfall or extra passes. | required |
| description-matches-diff | The PR description's claims about what the change does, read against the diff | Every change the description claims is actually in the diff, and the description does not leave out a substantive change a reviewer needs to know about (new behavior, new logic, a removed feature). A summary-level description that does not list every file passes. Fails when the description claims something the diff does not do, or the diff makes a substantive change the description never mentions. | required |
| evidence-observable | The test evidence read against the plan's test plan and the issue's described behavior | The after is pasted command output from the plan's repro or test steps, and it shows the behavior the plan said would change. The before can be pasted output, a stated before result, or the repro evidence already in the plan or issue. Fails when the after is only a claim like "tested, works" with no output, or the after shows nothing that changed. An honestly reported failing result with its reason passes. | required |
| repo-checks-run | The test evidence and the description's Testing section, read against the checks the repo's PR template, contributing docs, or the plan name | The PR shows the result of the repo's own checks or test suite. A pasted output line or a stated result such as "make test: 120 passed" counts. A check that fails or cannot run passes when its result and the reason are stated. Fails when the repo or plan names checks to run and the PR shows no sign any were run, or claims a pass that its own pasted output contradicts. Where neither the repo nor the plan names checks, this passes. | required |
| diff-clean | The diff's hunks, read for content unrelated to the plan's change | The diff contains only the change: no leftover debug prints or logging, no commented-out code, no stray files, and no unrelated refactors, formatting churn, or cleanups the issue does not need. Fails when any such hunk is present, even if the description explains it. | required |
| standards-met | The PR title and description, read against the repo's PR template, contributing rules, and stated AI policy (the repo-facts block in eval mode) | Every section the PR template asks for is filled in, the issue is linked as the template asks (for example Closes #N), and every disclosure the repo requires is present. Where the repo requires a section, link, or disclosure, its absence is a fail, not a neutral. Where the repo states no requirement, this passes. | required |
| title-states-change | The PR title, read against the diff | The title names the actual change in plain words, not a vague "fix" or "update". | preferred |

## Verdict rule

Accept if every required check passes. Any required check graded fail or unclear produces reject. Preferred checks never change the verdict. Unclear counts as fail: a PR that cannot be verified from the package is not ready to submit. An honestly disclosed shortfall is not a fail: when the plan's Deviations or the description says what was left out or could not be run, and why, grade the affected check on whether the disclosure is accurate, not on whether everything was done.
